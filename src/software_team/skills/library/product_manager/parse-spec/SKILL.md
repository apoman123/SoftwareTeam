# Parse the spec

Read the stakeholder spec closely and extract:

- The **business goal** — the outcome the stakeholder actually wants.
- The **actors / personas** who interact with the system.
- The concrete **use-cases** (what each actor needs to do).
- **Non-functional requirements** (performance, security) and anything marked **out of scope**.

Separate problem from solution: capture *what* the user needs, not *how* to build it.
Flag anything ambiguous as an explicit open question instead of silently assuming.
