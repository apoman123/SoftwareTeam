# Write the user manual and release notes

Translate shipped features into documentation the **end user** can follow.

- **User manual** — for each feature, what it does and the step-by-step way to use it, in plain language (no jargon, no implementation detail).
- **Release notes** — what changed this release, grouped as **Added / Changed / Fixed**.
- Anchor every entry to its user story so the value is clear (the *why*, not just the *what*).

Write for the person using the product, not the person who built it.
